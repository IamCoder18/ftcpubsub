# Install

Synapse is distributed as a Maven artifact, `com.aaravlabs:synapse:0.4.0`, published to **Maven Central**. Maven Central needs no authentication — if your project already has `mavenCentral()` in its repositories (the FTC template does), you can add the dependency and you're done:

```groovy
dependencies {
    implementation 'com.aaravlabs:synapse:0.4.0'
}
```

> **GitHub Packages?** Synapse is also mirrored on GitHub Packages at
> `maven.pkg.github.com/IamCoder18/synapse`. That mirror requires a GitHub
> token with the `read:packages` scope even for public packages — a GitHub
> restriction, not a Synapse one. The rest of this page walks through that
> setup, useful if your team already authenticates against GitHub.

## Prerequisites

- An FTC project built on the standard [`FtcRobotController`](https://github.com/FIRST-Tech-Challenge/FtcRobotController) template (uses `build.dependencies.gradle`).
- A GitHub account. The token needs only the `read:packages` scope — nothing else.
- Android Studio with the FTC project already syncing.

## Step 1 — Configure a GitHub token

Create a [personal access token](https://github.com/settings/tokens) with the `read:packages` scope, then put it in `~/.gradle/gradle.properties` (never commit this file):

```properties
githubUser=<your-github-username>
githubToken=<your-token>
```

> **Why a token at all?** GitHub Packages requires authenticated downloads even when the package is public. This is a GitHub restriction, not a Synapse one. The token is read-only for packages and never leaves your machine.

If you are on a team, each member (and the driver station's build environment) needs their own token in their own `gradle.properties`.

## Step 2 — Add the repository and dependency

Open `build.dependencies.gradle` in your FTC project and add the repository and the dependency.

**Groovy DSL** (the default FTC template):

```groovy
repositories {
    mavenCentral()
    google()
    maven {
        url = uri("https://maven.pkg.github.com/IamCoder18/synapse")
        credentials {
            username = findProperty("githubUser") ?: System.getenv("GITHUB_USER") ?: System.getenv("GITHUB_ACTOR")
            password = findProperty("githubToken") ?: System.getenv("GITHUB_TOKEN")
        }
    }
}

dependencies {
    implementation 'com.aaravlabs:synapse:0.4.0'
}
```

**Kotlin DSL** (if your project uses `build.dependencies.gradle.kts`):

```kotlin
repositories {
    mavenCentral()
    google()
    maven {
        url = uri("https://maven.pkg.github.com/IamCoder18/synapse")
        credentials {
            username = (findProperty("githubUser") as String?)
                ?: System.getenv("GITHUB_USER")
                ?: System.getenv("GITHUB_ACTOR")
            password = (findProperty("githubToken") as String?)
                ?: System.getenv("GITHUB_TOKEN")
        }
    }
}

dependencies {
    implementation("com.aaravlabs:synapse:0.4.0")
}
```

> **Using a version catalog or a newer SDK?** The coordinates stay the same — only the surrounding syntax changes. Keep the `maven { ... }` block as-is.

## Step 3 — Sync and verify

Sync Gradle (the `Sync Now` banner, or the Gradle elephant in Android Studio), then confirm the JAR landed:

```bash
./gradlew dependencies --configuration debugRuntimeClasspath | grep synapse
```

You should see `com.aaravlabs:synapse:0.4.0` in the output.

> **Sync fails with 401 Unauthorized?**
> 1. Check that `githubUser` and `githubToken` are spelled exactly like that in `~/.gradle/gradle.properties`.
> 2. Check that the token has `read:packages`.
> 3. Run `./gradlew --refresh-dependencies` once to force re-authentication.
> 4. If you copied the token with surrounding whitespace, remove it.

> **Sync fails with "Could not resolve com.aaravlabs:synapse"?**
> Make sure the `maven { ... }` block is inside `repositories { }` (not `buildscript`), and that the credentials block uses `findProperty` exactly as shown.

## R8 / minification

Synapse ships its ProGuard keep rules inside the JAR at `META-INF/proguard/synapse.pro`, so `minifyEnabled` builds work with no extra configuration. The keep rules are exercised in CI by running the full test suite through R8 minification.

## What you get

A ~40 KB JAR with zero runtime dependencies, containing:

- `Orchestrator` — the pub/sub bus and thread owner.
- The four annotations: `@SubscribedTo`, `@RunPeriodically`, `@RunnableAction`, `@OnHardwareThread`.
- The FTC layer: `SafeOpMode`, `HardwareActions`, `SafeDevice`, `SafeHardwareMap`, `GamepadAdaptor`.
